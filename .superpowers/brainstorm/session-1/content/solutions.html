实施方案对比

修复数据准确性问题的 3 种方案

方案 A：直接修复法

优点

  • 改动最小，只修改计算逻辑
  • 快速交付，风险低
  • 不需要修改数据库查询

缺点

  • 仍然依赖多次查询，性能无改善
  • N+1 查询问题依然存在
  • 缺少测试保障，可能引入新问题
主要改动
  • 修复 StudentProfileService.getKnowledgePointStats() 计算逻辑
  • 修复 StudentProfileService.buildWrongTypePie() 真实统计
  • 修复 ClassProfileService.buildKnowledgeMastery() 掌握率公式
  • 修复 ClassProfileService.buildKnowledgeRadar() 计算

方案 B：重构数据源法

优点

  • 从数据库层面正确聚合，数据最准确
  • 可以一次性解决 N+1 查询问题
  • 性能最优，减少多次数据库查询

缺点

  • 改动较大，需要修改 Mapper 和 SQL
  • 需要编写复杂的聚合查询
  • 开发周期较长
主要改动
  • 新增 AnswerSheetMapper 聚合查询方法
  • 新增 QuestionMapper 知识点统计方法
  • 重写 Service 层，使用聚合查询结果
  • 可能需要新增数据库视图或复杂 SQL

方案 C：混合方案（推荐）

优点

  • 分阶段实施，先快速修复后优化
  • 平衡风险和效果
  • 可以添加单元测试保障质量
  • 短期能看到效果，长期性能也改善

缺点

  • 需要分阶段实施，不是一次性完成
  • 需要协调前后端改动节奏
实施步骤
  • 阶段 1：修复 Service 层计算逻辑（直接修复法）
  • 阶段 2：添加单元测试验证数据准确性
  • 阶段 3：优化查询，引入聚合查询（重构数据源法）
  • 阶段 4：前端适配和验证

方案选择

直接修复法

快速修复，最小改动

B

彻底解决，性能最优

C

混合方案（推荐）
